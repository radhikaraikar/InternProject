# Self-Correcting RAG Pipeline

A Retrieval-Augmented Generation system that detects when retrieved context is **insufficient or contradictory** — and refuses to hallucinate.

**Live Demo:** [Streamlit Community Cloud URL — fill in after deploy]  
**Track:** Self-Correcting RAG Pipeline (Hackathon)

---

## Problem Statement

Standard RAG systems retrieve the top-k chunks and generate an answer regardless of retrieval quality. When context is weak or two sources disagree, the model happily hallucinates. This project adds a self-correction layer that:

1. **Checks retrieval confidence** via cosine similarity scores before calling the LLM
2. **Detects contradictions** across sources using a fast LLM judge (structured JSON output)
3. **Branches on the result** — grounded answer, re-query + clarify, or explicit contradiction surfacing

## Architecture

```
User Query
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│  A. RETRIEVAL                                           │
│     ChromaDB cosine similarity → top-5 chunks + scores │
└──────────────────────────┬──────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│  B. CONFIDENCE GATE                                     │
│     top score < 0.45 → reformulate query → re-retrieve  │
│     still low → return clarification request            │
└──────────────────────────┬──────────────────────────────┘
                           │ (score OK)
                           ▼
┌─────────────────────────────────────────────────────────┐
│  C. LLM JUDGE (Claude Haiku — fast classifier call)     │
│     Prompt → JSON: {sufficient, contradictory,          │
│                     reasoning, conflicting_claims}       │
└──────────────────────────┬──────────────────────────────┘
                           │
              ┌────────────┼────────────────┐
              │            │                │
         contradictory  insufficient    sufficient
              │            │                │
              ▼            ▼                ▼
       Surface       Re-query once    Generate grounded
       conflict      → clarify if     answer with
       to user       still weak       citations
```

**Ingestion pipeline:** Mixed docs (PDF, scanned image, TXT, DOCX) → OCR fallback via pytesseract → RecursiveCharacterTextSplitter (800 chars / 150 overlap) → sentence-transformers/all-MiniLM-L6-v2 embeddings → ChromaDB (local, persisted)

## Setup & Run Locally

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

> OCR requires Tesseract installed on your system:
> - **Windows:** download from [UB-Mannheim/tesseract](https://github.com/UB-Mannheim/tesseract/wiki)
> - **Mac:** `brew install tesseract`
> - **Linux:** `sudo apt install tesseract-ocr`

### 2. Set API key

```bash
# Windows
set ANTHROPIC_API_KEY=sk-ant-...

# Mac/Linux
export ANTHROPIC_API_KEY=sk-ant-...
```

### 3. Ingest sample documents

```bash
python ingest.py
```

### 4. Run the app

```bash
streamlit run app.py
```

### 5. Run the evaluation harness

```bash
python eval_harness.py
```

## Deployment (Streamlit Community Cloud)

1. Push this repo to GitHub (public)
2. Go to [share.streamlit.io](https://share.streamlit.io) → New app → select repo
3. Set **Main file path:** `app.py`
4. Under **Advanced settings → Secrets**, add:
   ```toml
   ANTHROPIC_API_KEY = "sk-ant-..."
   ```
5. On first load, the app rebuilds the Chroma index from `data/` automatically (cached with `st.cache_resource`)

## Known Limitations & What's Next

- **Confidence threshold (0.45)** was tuned empirically on these 3 docs — needs calibration for larger corpora
- **OCR quality** degrades on low-DPI scans; pre-processing (deskew, denoise) would help
- **Judge prompt reliability** depends on Claude following the JSON schema — added `.strip()` + fallback parsing for robustness
- **No streaming** — answers appear all at once; streaming responses would improve UX
- **Single-turn only** — multi-turn conversation memory would let users answer clarifying questions inline
- **With more time:** hybrid BM25 + dense retrieval (reciprocal rank fusion), cross-encoder reranking, persistent conversation threads

## Tech Stack

| Component | Choice | Why |
|---|---|---|
| LLM | Claude 3.5 Haiku | Fast, cheap, follows structured JSON reliably |
| Embeddings | sentence-transformers/all-MiniLM-L6-v2 | Free, local, no API cost |
| Vector store | ChromaDB | Zero infra, persists to disk, cosine similarity built-in |
| OCR | pytesseract + pdf2image | Standard, works offline |
| UI | Streamlit | Fastest path to a public deployed link |
| Orchestration | Plain Python + LangChain text splitter | Simple, debuggable |
